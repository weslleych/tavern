# Decision records

These records preserve the context, choices, and consequences of accepted changes. The [roadmap](../roadmap.md) tracks scope and delivery; the [implementation plan](../character_system_plan.md), [architecture](../architecture.md), and [data models](../data-models.md) describe current behavior.

| Record                                                               | Status   | Recorded   | Scope                                                                                                                           |
| -------------------------------------------------------------------- | -------- | ---------- | ------------------------------------------------------------------------------------------------------------------------------- |
| [ADR 0001: Phase 4 GM coordination](0001-phase-4-gm-coordination.md) | Accepted | 2026-10-04 | Six follow-up requests after the initial phase 4 scope, their defaults, permissions, compatibility, and interface consequences. |

Add records sequentially when a decision changes a meaningful domain boundary, scope, or architectural trade-off. When a later decision replaces an accepted one, add a new ADR, link the records, and mark the old decision as superseded. Update the current specifications without rewriting the historical rationale as if the later choice had always been the original scope.
